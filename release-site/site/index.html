故障、容量与数据保护，在同一套判断链路里。

不是把命令输出搬到浏览器，而是把“发生了什么、影响什么、下一步做什么”组织成可执行的界面。

监控与预测

从一块盘的健康趋势，到整台阵列的影响面。

健康评分、告警中心、磁盘磨损、SMART 增长趋势与机箱槽位拓扑共用一套状态语义。异常不会被藏在二级页面里。

  • 控制器、VD、PD、NVMe 与 SAS/SES 背板统一视图
  • 告警确认、恢复、维护窗口与 Webhook / 邮件通知
  • 多控制器并列展示，跨卡固件与配置一致性检查

存储与缓存

把文件系统、SSD 加速和共享放在一个工作面。

块设备、挂载、bcache 缓存集、命中率、桶水位、脏数据回写与 NFS 共享可以一起查看和管理，不必在几个终端之间来回切换。

  • bcache 创建、绑定、停用、恢复与应急只读挂载
  • 缓存命中率、服务率、可用比例和 GC 状态趋势
  • 只读挂载回读验证，避免“看似可写”的共享配置

数据保护

备份不是“跑成功一次”，而是恢复链可验证。

全量 / 增量、本地 / NFS / SSH 目的地、SHA-256 manifest、链恢复、定时任务与自动恢复演练组成完整闭环。

  • 恢复默认不覆盖，先做 dry-run 与归档完整性验证
  • 保留策略按增量链计算，失败任务进入告警
  • 根分区恢复默认阻断，危险目标必须显式放行

性能与诊断

用户说“IO 很慢”时，给出证据，而不是再跑一条第一条命令。

实时 IOPS、带宽、延迟和利用率与只读慢盘诊断并列。基准测试支持页缓存预热、丢弃缓存、限速与隔离临时文件。

  • 顺序 / 随机读写、队列深度、线程数与块大小可组合
  • 设备角色识别，自动排除 USB 系统盘作为测试目标
  • 测试文件只写模块自己创建的位置，结束后自动清理

危险动作慢下来，状态变化留下来。

换盘、重建、扩容、缓存销毁、擦除与恢复操作统一交给异步任务引擎。用户能看到当前步骤、结果输出和失败原因。

  1. 确认影响目标与后果
  2. 进入任务串行执行
  3. 持续追踪进度与输出
  4. 留下证据可重试审计

报表、策略与多机视图，让问题可以被交接。

值班人员离场后，下一位同事仍能看懂发生了什么。

从安装包到可访问的界面，只需要一条命令。

安装器自动检查环境、创建独立 Python 虚拟环境、保留旧数据、注册 systemd 服务并验证首页。

  1. 01
    解压发布包

    下载后校验 SHA-256，再解压到任意管理目录。

  2. 02
    准备 StorCLI

    从 Broadcom 获取合法的 storcli64，安装器不代为分发。

  3. 03
    执行安装

    脚本完成依赖、服务、开机自启和健康检查。

root@storagebash
tar -xzf datamax-lsi-1.10.27.tar.gz
cd datamax-lsi-1.10.27
sudo bash install.sh \
  --storcli-source /path/to/storcli64
运行环境 Linux x86_64 systemd Python 3.9+ Broadcom StorCLI 端口默认 5200，可在安装时修改。
