DATAMAX-LSI · OPERATIONS MANUAL

从第一次登录，到一次安全的磁盘更换。

本手册面向首次接触 DataMax-LSI 的运维人员和售后工程师。按页面顺序操作即可完成部署、 日常巡检、故障判断、危险操作与数据恢复。涉及磁盘、阵列、格式化和缓存销毁的章节请先读完整步骤。

适用版本 1.10.27 Linux · systemd 建议阅读 20 分钟

安装前准备

DataMax-LSI 运行在连接 RAID 卡的存储服务器上。Web 服务默认监听 5200 端口，数据默认写入安装目录下的 data/。

项目要求检查命令
操作系统Ubuntu / Debian / RHEL 系 / openSUSE，需 systemdsystemctl --version
Python3.9 或更高python3 --version
StorCLIBroadcom MegaRAID 对应版本，需单独取得storcli64 show
SMARTsmartmontools，安装器会补齐smartctl --version
磁盘空间建议系统盘至少保留 2 GBdf -h /
不要直接覆盖生产数据目录。 安装器会保留已有 data/、PAM 映射和自定义环境配置；仍建议在升级前单独备份 /opt/lsi-raid-monitor/data。

安装与启动

将发布页下载的安装包上传到服务器，完成校验后解压。StorCLI 不随公开安装包重新分发，可以使用系统已有版本，也可以在安装时显式传入。

sha256sum datamax-lsi-1.10.27.tar.gz
tar -xzf datamax-lsi-1.10.27.tar.gz
cd datamax-lsi-1.10.27
sudo bash install.sh --storcli-source /path/to/storcli64

安装器会检查 Python 和端口、创建独立虚拟环境、安装 Web 依赖、保留旧数据、注册并启动 datamax-lsi.service，最后访问本机首页进行健康检查。

systemctl status datamax-lsi
journalctl -u datamax-lsi -f
curl -I http://127.0.0.1:5200/

常用安装选项

参数用途
--port 8080改变 Web 端口
--data-dir /var/lib/datamax-lsi把数据目录移出应用目录
--install-extras追加 fio、bcache、NVMe、IPMI、XFS 等工具
--check只做环境检查，不修改系统
--allow-missing-storcli硬件尚未到货时先安装只读界面
默认只补基础依赖并且不升级系统现有软件包。需要完整性能、bcache 和硬件传感器能力时，使用 --install-extras，或在对应功能页按需安装。

首次登录与权限

系统使用服务器本地 PAM 认证，不维护独立网页面板密码。首次打开浏览器访问 http://服务器IP:5200，输入 Linux 系统用户名和密码。

角色按以下优先级映射：

  1. admin：root，以及 LSI_PAM_ADMIN_USERS 或 LSI_PAM_ADMIN_GROUP 命中的用户。
  2. operator：由 LSI_PAM_OPERATOR_USERS/GROUP 指定，可执行运维操作。
  3. auditor：由 LSI_PAM_AUDITOR_USERS/GROUP 指定，用于审计查看。
  4. viewer：其他系统账号，只能查看，不能修改配置或执行危险操作。

映射配置位于 /etc/datamax-lsi.env。修改后重启服务生效。

界面与状态阅读

左侧导航分为监控概览、文件管理、性能中心、日志中心、运维中心、用户与授权、报表中心和多机管理。每个页面再按标签分组，避免把长页面堆成一条没有边界的流水账。

状态使用固定语义：青绿色代表正常，琥珀色代表需要关注，红色代表严重或失败。磁盘状态保留 StorCLI 原始词，如 Onln、UGood、Offln、Failed，并在旁边显示中文解释。

页面每 60 秒刷新状态，系统资源每 5 秒刷新。页面数据与“最后采集时间”以服务器时钟为准； 时间跨度超过采集间隔两倍时，界面会提示数据过期。

监控概览

“总览”是值班接班的第一屏。先看综合健康评分与“运行态势”，再决定进入告警、容量或磁盘标签。

标签说明

  • 总览：优先关注、容量预测、控制器与阵列保护状态。
  • 系统与文件：CPU、内存、负载、文件系统用量和主机信息。
  • 告警与健康：未处理告警、确认、维护窗口、磁盘磨损排行。
  • 磁盘与阵列：槽位拓扑、虚拟磁盘、物理磁盘、NVMe 明细。
  • 维护与趋势：温度 / IO / 文件系统趋势、巡读和一致性检查。
  • 授权：版本能力、离线授权安装与移除。

磁盘与阵列运维

物理盘表是判断换盘的主要入口。关注槽位、状态、温度、ME/OE/PF、重建与预测等级。点击磁盘可以查看 SMART、所在阵列和可用动作。

安全换盘步骤

  1. 确认故障盘槽位、序列号和 DG/VD 成员关系，避免凭盘符判断。
  2. 如果阵列尚可运行，先检查热备策略；只有专用或全局热备盘会自动接替。
  3. 记录配置快照与任务编号，再进行离线、定位灯或更换操作。
  4. 新盘插入后确认状态为 UGood 或 Onln，再把盘加入阵列或设为热备。
  5. 在重建进度中持续查看百分比、速率和预计时间，不要在重建中重启控制器。
不是所有未配置盘都会自动参与重建。只有虚拟盘成员或被明确设置为热备的盘才应参与； 发现无关磁盘进入重建时，应立即停止并检查阵列成员与热备配置。

文件、缓存与共享

文件管理页面从块设备开始，展示系统盘、虚拟盘、bcache 卷和挂载点。格式化和初始化会破坏数据，必须先确认盘符、挂载状态和备份。

bcache 使用顺序

  1. 用 SSD / NVMe 创建缓存集，明确 backing 数据盘和 cache 缓存盘。
  2. 新建缓存集会清理所用设备的旧文件系统标记；已有数据的盘必须先备份。
  3. 缓存模式优先从 writethrough 开始，确认稳定后再切到 writeback。
  4. 切换出 writeback 前先确认脏数据回写，缓存盘掉线时不要直接销毁缓存集。
  5. 缓存盘永久丢失时，使用应急只读回环偏移方式挂载 backing 数据盘，先保全数据。

NFS 共享可指定客户端网段、读写模式和同步选项。Web 中的挂载结果会回读 findmnt，如果分区被系统挂成只读，客户端写入会被明确拒绝并显示真实原因。

数据备份与恢复

数据备份使用文件级 tar 与 zstd，支持全量、增量链、本地目录、NFS 挂载和远程 SSH。备份源端只读，恢复默认先执行 dry-run，不覆盖目标现有文件。

一次完整备份

  1. 本地目录或 NFS 使用路径选择器；远程 SSH 需先选择目的地类型，再直接填写 user@host:/path，并提前配置免密登录。
  2. 首次运行全量；后续可按备份链运行增量，保留策略会按链计算。
  3. 归档完成后查看 manifest、SHA-256 和一致性等级。
  4. 需要恢复时先执行预览，确认变更数量、覆盖策略和目标位置。
  5. 定期执行恢复演练；失败会进入告警，不会静默跳过。

性能测试与诊断

性能中心用于回答“为什么现在很慢”。慢盘诊断是只读分析，基准测试才写入文件；两者在界面上有明确区分。

基准测试注意事项

  • 确认目标设备不是 USB 系统盘，生产盘测试前必须评估业务影响。
  • 顺序与随机测试分别设置块大小、线程数和队列深度。
  • 需要可比较结果时使用相同预热时间，并按需选择页缓存丢弃。
  • 测试文件由模块创建和清理；不要在测试过程中手动删除临时目录。

运维中心

运维中心承载机箱盘位、硬件传感器、SES 背板、维护计划、控制器策略、PHY 错误与配置快照。

异步任务

危险操作会生成任务记录。打开右侧任务中心可查看当前步骤、进度、命令输出和失败原因。只有标记为可重试的任务才提供重试按钮。

维护计划

巡读、一致性检查和 SMART 自检可以按日、周、月安排。执行前确认业务峰谷，并在控制器策略中设置合理的重建和巡检速率限制。 RAID0 没有镜像或校验数据，控制器不允许执行一致性检查，界面会显示“不适用”；这类阵列应依靠 SMART、介质错误监控和备份保障数据安全。

告警与报表

告警设置支持温度阈值、SMART、预测性故障、控制器、BBU、磁盘和阵列状态变化。告警确认只会停止重复提醒，不会修复硬件。

维护窗口会记录告警但仍静默通知，适合换盘、背板维修和计划性重启。Webhook 可以接钉钉、飞书或企业微信机器人。

多机与接口

多机管理通过每台机器上的采集令牌汇总状态。节点可按分组、在线状态和未处理告警筛选，中心节点可以汇总告警并执行有限的管理动作。

系统同时暴露 Prometheus 指标、REST API 和 Grafana 面板。自动化系统应使用只读或最小权限账号，不要把 PAM 管理员口令写入脚本。

安全与日常维护

  • 默认 HTTP 适合受控内网。对外提供服务时应在前面部署 HTTPS 反向代理并设置安全 Cookie。
  • 服务需要 root 访问 /dev、/sys、PAM、挂载和 StorCLI；不要用普通用户启动完整控制面。
  • 只给操作员分配 PAM 组权限，审计账号使用 viewer / auditor 角色。
  • 每周查看未处理告警、容量预测、SMART 增长和最近失败任务。
  • 每月导出一次配置快照，并演练一次数据恢复。

故障排查

页面打不开

  1. systemctl status datamax-lsi 看服务是否运行。
  2. ss -ltnp | grep 5200 确认端口和进程。
  3. journalctl -u datamax-lsi -n 100 查看 Python 或启动错误。
  4. 检查防火墙是否放行访问来源到 TCP 5200。

磁盘数据为空

先执行 storcli64 show，再确认 /etc/datamax-lsi.env 中的 STORCLI_PATH。StorCLI 版本与控制器代际不匹配时，命令可能返回 0 但内部状态为 Failure。

登录失败

确认使用 Linux 系统账号，并检查 LSI_PAM_SERVICE 是否为系统可用的 PAM 服务。root 通常映射为 admin；其他用户默认至少具有 viewer 只读权限。

升级失败

安装器会停止新服务并恢复上一版应用与 systemd 单元，数据目录不删除。检查终端输出的备份路径，以及 /var/log/syslog 或 journalctl 中的错误。
